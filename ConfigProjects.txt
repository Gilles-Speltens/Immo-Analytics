Configurer le chemin vers le fichier NLog de chaque projet.

--- Interface API ---
Configurer le chemin de l’API dans les fichiers appsettings.json des projets API_Tracker_Interface ainsi que des différents sites web utilisant l’API.
Configurer également le mot de passe de l’interface de l’API.

--- Tracking API ---
Configurer le temps de rotation des logs (en minutes) utilisé par l’API pour générer de nouveaux fichiers de logs.

Créer un dossier destiné à contenir les fichiers de WhiteList de l’API (les fichiers seront créés automatiquement), puis ajouter le chemin de ce dossier dans le fichier appsettings.json du projet APITracker.

Faire de même pour un dossier destiné à contenir les différents fichiers de logs générés par l’API, puis ajouter son chemin dans le fichier appsettings.json.
Attention : ce dossier devra être partagé entre l’API et le MessageParser.

Ajouter ensuite l’adresse IP de l’interfaceAdmin afin qu’elle puisse accéder à la WhiteList de l’API.

Ajouter dans Program.cs app.UseSession(); et en dessous app.UseMiddleware<RequestTrackingMiddleware>();

--- Message Parser ---
Ajouter le chemin du dossier contenant les différents fichiers de logs créés précédemment au paramètre trackingDirectory.

Créer un dossier archive qui contiendra tous les fichiers de logs une fois traités par le MessageParser, puis ajouter son chemin au paramètre archiveDirectory.

Créer un dossier invalid qui contiendra les logs invalides traités, puis ajouter son chemin au paramètre invalidDirectory.

Créer un dossier work qui contiendra les fichiers en cours de traitement par le MessageParser, puis ajouter son chemin au paramètre workingDirectory.

Configurer la durée maximale d’une session utilisateur (en minutes) afin de permettre au MessageParser de déterminer si une session est toujours active ou non.

Créer et configurer une base de données MariaDB à l’aide des tables contenues dans le fichier TrackingDB.sql, puis ajouter les paramètres de connexion (server, user, password, database).

Si un fichier ne peut pas être inséré dans la base de données, celui-ci restera bloqué dans le dossier working, indiquant qu’un problème est survenu.
Dans ce cas, le MessageParser ne pourra plus traiter d’autres fichiers tant que le fichier problématique restera présent dans le dossier working.
Le message d’erreur sera écrit dans le fichier configuré par NLog, et une nouvelle entrée sera ajoutée dans la table File_Monitoring avec le statut FAILED.
Pour remettre le MessageParser en fonctionnement, il faudra corriger manuellement le problème présent dans le fichier, puis déplacer ce dernier dans le dossier tracking afin qu’il soit traité à nouveau.
